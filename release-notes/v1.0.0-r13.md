# r13：出包元数据修复 + guest 实跑验证 + QEMU 手动 CI

本轮没有功能改动（脚本/前端与 r12 一致），只修打包与验证链路。

## 修复（真实缺陷，来自 guest 实跑与 ADB 审计）

- **apk 文件属主错误**：`apk.static mkpkg` 直接以当前用户打包，ADB 里记录成 `user: <构建者> / group: <构建者>`，装到设备后文件属主非 root。现改为「root / sudo chown / `unshare -r`」三选一取得根属主（`scripts/ci/build-pkgs.sh`），并新增 `verify-pkgs.sh` 断言：ADB 中不得出现非 root 属主。
- **apk 目录权限 0777**：git/Windows 检出的目录模式不可靠，曾把 `etc`、`usr` 等目录打成 `0777`。`scripts/ci/stage.sh` 统一目录 `0755`，并新增断言禁止 apk 内出现 `0777`。
- **apk 缺 conffiles 元数据**：apk v3 不再把 conffiles 放在控制区，而是包内 `/lib/apk/packages/<pkg>.conffiles` 与 `.conffiles_static`。缺失时 apk 不知道 `/etc/config/ferry` 是配置文件。现按 SDK `include/package-pack.mk` 的格式生成这两份文件（外加 `.list`），并断言登记了 `/etc/config/ferry`。
- **出包不可复现**：`stage.sh` 把 stage 内所有文件/目录 mtime 归一到 `SOURCE_DATE_EPOCH`（默认 `1600000000`），同一提交重复打包得到同样的 ADB mtime。
- **打包依赖说明对齐**：CI 产物仍只声明 `luci-base`；`Makefile` 增加注释说明为什么 `kmod-nft-tproxy` 等不能做硬依赖（25.12 x86 targets feed 未发布 `kmod-nf-tproxy`，硬依赖会让 25.12 整个包安装失败）。

验收脚本的一处稳健性调整：重启后立即读取 `nft list tables` 在 25.12 上出现过一次瞬时误判，因此改为 20s 有界收敛窗口（实测两次复跑均为 0s 命中，窗口内不出现仍判失败），失败时打印 `nft list tables`、`/etc/ferry` 与 `logread` 供定位。

## 官方 SDK 重打包评估（结论）

- 24.10 / 25.12 SDK 都能下载并解压；SDK 的 `apk` 是动态二进制 + `runas.so`，配合 host 侧 `fakeroot` 才写入 root 属主；`apk mkpkg` 默认**不签名**。
- 本机（WSL、无 root、无完整宿主构建依赖）跑 SDK 的 `make package/.../compile` 无法闭环：缺 `make`/`gawk`/若干 perl 模块，补装后仍受 perl 版本错位阻塞。因此本轮不引入 SDK 构建，仍用 `apk.static` 直接出包（已对齐 SDK 的包结构）。
- apk 签名：`apk mkpkg --sign <RSA 私钥.pem>` 实测可用（本地生成 2048 位密钥 → 出包 → `apk verify`）。但设备侧必须信任对应公钥，否则校验结果为 `UNTRUSTED signature`，安装要加 `--allow-untrusted`。私钥对应 SDK 的 `BUILD_KEY_APK_SEC`（`private-key.pem`），SDK 不附带，必须由使用者自备；放 CI 只能是 secret。因此发布产物保持未签名（否则普通用户装不上），签名属于「自建固件/自带公钥分发」场景的独立决策。
